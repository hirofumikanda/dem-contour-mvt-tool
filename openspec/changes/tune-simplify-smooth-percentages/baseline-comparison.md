# ベースライン比較結果（Issue #38 / tasks.md 1.1, 1.2）

デフォルト値（`SIMPLIFY_PERCENTAGE_100M=20%`, `SIMPLIFY_PERCENTAGE_500M=8%`, `CHAIKIN_ITERATIONS=2`, `SIMPLIFY_PERCENTAGE_POST_SMOOTH=25%`）で`tif/`のサンプルデータから生成した`build/contours.pmtiles`を、`viewer`で国土地理院最適化ベクトルタイル（`std.json`）とz11・z13（100m帯）・z7・z10（500m帯）で比較した。

## 手法

- `bin/make-contour-pmtiles.sh`をデフォルト値で実行し、`build/contours.pmtiles`を生成（`viewer/public/contours.pmtiles`はこれへのシンボリックリンク）。
- `viewer`（`npm run dev`）をヘッドレスChromium（Playwright）で開き、URLハッシュ（`#<zoom>/<lat>/<lng>`、中心は`build/contours.pmtiles`のデータ範囲中心 `35.362176, 138.065186`）で各ズームに遷移。
- `#before`（自作）・`#after`（GSI）のCSS `clip`を操作してどちらか一方のみを表示させ、同一ビューポート・同一ズームでの単独スクリーンショットを取得して比較（スワイプ操作のドラッグ位置に依存しない、両地図同条件での比較）。

## ズームごとの所見

### z13（100m帯・最詳細側）
自作・GSIともに概ね滑らかで丸みのある曲線になっており、全体的な「角張らない」印象は自作でも達成できている。GSIの方がわずかに曲線が滑らかで、かつ等高線の本数が多い（密度が高い）が、これはGSIが低ズームでも常時10m間隔相当のデータを内部で保持し、ズームごとに自動的に一般化しているのに対し、自作は100m間隔データそのものを使っている設計上の違いによるもの（本Changeのスコープ外、`add-contour-viewer/design.md`にも既知の差異として記載あり）。**形状の滑らかさという観点では、z13時点のデフォルト値は大きく外していない。**

### z11（100m帯・最広域側）
自作の等高線は密集しすぎており、稜線が複雑な箇所では線同士がほぼ重なり合って判読しづらく、標高ラベルも重複して見づらい。同じ実世界範囲をGSIで見ると、線ははるかに疎で整理されており、判読性が高い。`--no-line-simplification`によりz11-13で同一の簡略化済みジオメトリを使い回す仕様上、z13で許容できる密度がz11では過密になっている。**`SIMPLIFY_PERCENTAGE_100M=20%`はz11の見た目を基準にするとやや保持しすぎ（簡略化が弱い）と考えられる。**

### z10（500m帯・最詳細側）
自作の等高線に明確な角張り（直線的なジグザグ）が見える。GSI側は同じ実世界範囲で非常に滑らかな曲線になっている。**`CHAIKIN_ITERATIONS=2`・`SIMPLIFY_PERCENTAGE_POST_SMOOTH=25%`（500m帯にも共通適用）では、500m帯の最詳細側において十分な滑らかさが得られていない。**

### z7（500m帯・最広域側）
サンプルデータの実世界範囲（PMTiles bounds: 経度約0.25°×緯度約0.084°、DEM 2次メッシュ2枚分＝十数km四方）が、z7の1タイルが覆う実世界範囲（中緯度で1辺約300km）に対して極端に小さく、1400px幅のビューポートで表示すると自作データの占める領域が数十px四方に縮退し、線が事実上不可視になる（`sqlite3`でz7タイル自体は存在し中身も確認済みだが、画面上では判読不能）。**z7は本サンプルデータでは目視比較の対象として機能しない。** 500m帯の「最広域側」の代理としては、実用上z10を最詳細側の基準として使い、z7相当の判断はスキップする（design.mdのRisksに記載済みの「サンプルデータのみでの調整」の制約の一種）。

## 後続Issue（#39, #40）への示唆

- 100m帯（#39）: z11の過密さを緩和するため`SIMPLIFY_PERCENTAGE_100M`をデフォルトの20%より下げる方向（より強い簡略化）を軸に候補値を検討する。ただしz13の見た目（現状ほぼ良好）を大きく損なわない範囲に留める必要がある。
- 500m帯（#40）: z10の角張りを緩和するため、`CHAIKIN_ITERATIONS`を増やす、または`SIMPLIFY_PERCENTAGE_POST_SMOOTH`を上げる（保持率を上げてChaikinの丸みをより残す）方向を軸に検討する。ただし`CHAIKIN_ITERATIONS`・`SIMPLIFY_PERCENTAGE_POST_SMOOTH`は100m帯と共有パラメータのため、100m帯側への影響も合わせて確認する。
- z7は本サンプルデータでは判断材料にならないため、500m帯の妥当性確認はz10（および可能ならz8・z9）を中心に行う。
